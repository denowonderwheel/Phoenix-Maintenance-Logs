PHOENIX TRACKER — DEMO SANDBOX SETUP
=====================================

This folder is a sandbox copy of the tracker. It shares NOTHING with the
live park app — separate database, separate logins, separate URL. Anything
a tester does here cannot touch real park data.

ONE-TIME SETUP (about 10 minutes, all in the Firebase console)
--------------------------------------------------------------
1. Go to console.firebase.google.com and sign in with your Google account.
2. Click "Add project". Name it something obviously fake, e.g.
   phoenix-tracker-demo. (Google Analytics: off is fine.)
3. Build > Authentication > Get started > enable "Email/Password".
4. Authentication > Settings > Authorized domains > Add domain:
      denowonderwheel.github.io
5. Build > Firestore Database > Create database > Production mode.
6. Firestore > Rules tab > paste the contents of firestore.rules
   (the same file the live app uses — it works unchanged) > Publish.
7. Build > Storage > Get started > create the default bucket
   (requires the Blaze plan; same location as Firestore, Production
   mode). Then Storage > Rules tab > paste the contents of
   storage.rules.txt > Publish. This enables photo attachments.
8. Project settings (gear icon, top left) > scroll to "Your apps" >
   click the web icon </> > register an app (any nickname) > copy the
   firebaseConfig values it shows you.
9. Open demo/index.html in a text editor, find the block marked with
   warning signs near the top of the <script> (search for PASTE-DEMO),
   and replace the placeholder values with the ones you copied.

That's it. Push the demo folder to the GitHub repo and it will be live at:
   https://denowonderwheel.github.io/Phoenix-Maintenance-Logs/demo/

FOR YOUR TESTER
---------------
- The FIRST person to sign up automatically becomes the demo's admin —
  no invite code needed. So either let your tester sign up first (they
  get the full admin experience: invite codes, roster, team management,
  reset-to-seed), or claim admin yourself and hand them an invite code.
- Suggest they hit Reference > Reset to seed (admin only, asks for their
  password) to fill the demo with the 132 realistic grease entries so it
  doesn't start empty.
- Sign-up is gated after the first user, so strangers finding the URL
  can't get in without an invite code. Still, claim that first account
  promptly after the demo goes live.

KNOWN DEMO LIMITATIONS
----------------------
- The paragraph-reference links into the manual PDFs only work when the
  file is opened locally with the PDFs next to it, same as the live app.

CLEANUP WHEN DONE
-----------------
Delete the Firebase demo project (console > project settings > scroll
down > Delete project) and remove the demo/ folder from the repo. Or
keep it around as your own sandbox for testing new features before they
go live.


VERSION 3 — ASK THE MANUALS (voice assistant) + LOGIN-ONLY MANUALS
===================================================================
Version 3 adds a "Ask the manuals" button: tap the mic, ask a question
("what torque for the fixed EC brake bolts?"), and it answers out loud from
the Phoenix manuals with the pages to check. Manuals now open only for
signed-in users, inside the tracker.

It needs server code (Cloud Functions in the functions/ folder) and a Claude
API key. One-time setup for the demo project (vekoma-demo):

1. Firebase console > vekoma-demo > Usage and billing: make sure the project
   is on the Blaze plan (Cloud Functions require it).
2. Put the manuals into the demo: sign in to the demo tracker as admin >
   Reference tab > Upload PDF… for each manual (OMM, PRT, DIA, OEM, TS).
   (Or Firebase console > Storage > create folder "manuals" > upload.)
3. Claude API key: console.anthropic.com > API keys > Create key. Add a
   little credit under Billing.
4. Deploy key for GitHub: console.cloud.google.com > pick vekoma-demo >
   IAM & Admin > Service accounts > Create service account
   (name: github-deploy, role: Owner — fine for the sandbox) > open it >
   Keys > Add key > JSON. A .json file downloads.
5. GitHub > this repo > Settings > Secrets and variables > Actions >
   New repository secret, twice:
     FIREBASE_SERVICE_ACCOUNT_DEMO  = the whole contents of that .json file
     ANTHROPIC_API_KEY              = the Claude API key
   Then delete the .json file from your computer/phone.
6. GitHub > Actions > "Deploy manual assistant" > Run workflow > demo.
   Takes about 3-5 minutes the first time.
7. Demo tracker > Reference tab > "Ask the manuals — search index" >
   Rebuild index & lock links. Takes a few minutes; keep the page open.
   This also switches off the manuals' old public download links.
8. Tap "🎤 Ask the manuals" and try it.

Every question and answer is saved in Firestore (collection assistantLog)
with the pages used and the tokens spent, so answers and cost can be checked.
Each user is limited to 60 questions a day (DAILY_QUESTIONS_PER_USER in
functions/index.js).

Never commit the manual PDFs to this repo — it is public and the manuals are
Vekoma-confidential. They live only in Firebase Storage.
